# Playbook и чек-лист: отдельный экспорт

Подготовлены 44 документа в `data/kb/onboarding`: 28 файлов Playbook и 16 записей CSV чек-листа. Статьи Хабра в эту папку не входят.

## Запуск на ПК с RTX 3070 Ti

Сначала закоммить и отправь изменения с подготовившего их ПК. На ПК с GPU обнови ветку:

```powershell
git switch RAG
git pull --ff-only origin RAG
```

Из корня проекта, с уже настроенным CUDA-окружением:

```powershell
$env:EMBEDDING_MODEL = 'Qwen/Qwen3-Embedding-0.6B'
$env:TOKENIZER_MODEL = 'Qwen/Qwen3-Embedding-0.6B'
$env:EMBEDDING_BATCH_SIZE = '8'
$env:CHUNK_TARGET_TOKENS = '300'
$env:CHUNK_MAX_TOKENS = '400'
$env:CHUNK_OVERLAP_TOKENS = '40'
.\.venv\Scripts\python.exe -u -m backend.rag.export_corpus --input data/kb/onboarding --output embeddings/onboarding-corpus.json --device cuda --resume --fail-fast
```

Настройки модели и токенизации автоматически читаются из корневого `.env`. Подготовка окружения описана в [PROJECT_GUIDE.md](PROJECT_GUIDE.md).

Не добавляй `--public-habr`: в этих документах уже есть полные метаданные и указан настоящий источник — пользовательский архив или CSV.

На ПК без CUDA, с установленными зависимостями, используй системный Python и CPU:

```powershell
python -u -m backend.rag.export_corpus --input data/kb/onboarding --output embeddings/onboarding-corpus.json --device cpu --resume --fail-fast
```

## Содержимое и происхождение

- `playbook/overview.md` содержит содержательные разделы исходного `readme.md`: о справочнике, команде, технологиях и показатели компании. Навигационный список репозитория исключён. Переименование не даёт экспортёру пропустить полезный документ как служебный README.
- Остальные 27 файлов Playbook сохранены с исходными именами. Внутренние ссылки на README обновлены до `overview.md`.
- Каждая запись чек-листа сохраняет заголовок, описание, срок, исходное имя CSV и номер записи. Повторяющиеся пункты не удаляются; роли исполнителей не выводятся из текста автоматически.
- Срок включён в название документа для эмбеддинга: если длинный пункт разделится, каждый чанк всё равно будет содержать период в `embedding_text`. Исходный заголовок отдельно сохранён в `metadata.source_title`.
- `origin=provided` означает предоставленный пользователем файл: это не утверждение о публикации в интернете и не синтетический текст.
- Для материалов этого набора явно указаны `min_role=intern`, `team=null`: они предназначены для общей базы стажёрских материалов. Метаданные не заменяют реализацию контроля доступа при поиске.
- `source_url` использует `archive:///...` или `attachment:///...`. Это идентификаторы исходников; веб-страницы по этим адресам не предполагаются.

## Результат

После успешного завершения появится `embeddings/onboarding-corpus.json`: полные тексты, метаданные, чанки и векторы по 1024 координаты. В итоговой строке должны быть `documents: 44`, `errors: 0`, `embeddings: true`; в JSON — `summary.complete: true`.

Готовый `embeddings/habr-corpus.json` остаётся отдельным файлом. Перенеси на ПК с БД оба JSON. Статьи Хабра пересчитывать не требуется.

Имя коллекции по умолчанию оставлено совместимым с ранее созданным Habr JSON (`avito-habr`). У документов разных наборов разные `source_key`: `playbook/...`, `internship/...` и числовые имена файлов Habr. При загрузке это позволяет добавить документы в ту же коллекцию, если модель и настройки совпадают. Альтернативное имя задаётся через `--collection-name`.

Схема `postgres/001_rag_schema.sql` дополнена происхождением `provided`. Если прежняя схема уже установлена, перед импортом этих документов понадобится миграция `postgres/002_provided_origin.sql`. Она подготовлена как файл и автоматически не запускается. Правила ролей и команд не менялись.
