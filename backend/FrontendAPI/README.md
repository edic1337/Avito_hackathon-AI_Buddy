# HTTP API вопросов

Пакет `GO/FrontendAPI` принимает запросы frontend и вызывает
`rag.Retriever.Answer`: поиск → `[]string` → `ModelAPI`. Пакет `ModelAPI`
не импортирует HTTP-слой, циклических зависимостей нет.

## Контракт frontend

```http
POST /question
Authorization: Bearer <токен текущего пользователя>
Content-Type: application/json

{"question":"Как получить VPN?"}
```

Ответ:

```json
{"error":"","question":"Как получить VPN?","answer":"..."}
```

Поля `access`, `role`, `team` из тела запроса больше не принимаются — вернётся
400. Заголовки `X-Role` и `X-Team` не используются. Права определяет сервер
по аутентифицированному пользователю. Поля ответа коллеги сохранены.

## Подключение

Создайте один пул БД, Store, HTTPEmbedder и Retriever при старте приложения,
как описано в основном README. Папка FrontendAPI — библиотека, не `package main`.
После загрузки `.env` и создания retriever из main можно вызвать:

```go
import "GO/FrontendAPI"

// retriever уже создан; пул БД остаётся открытым на всё время работы сервера.
if err := FrontendAPI.StartHTTPServer(retriever); err != nil {
    return err
}
```

Для этой точки входа задайте в своём `.env` серверный список демонстрационных
пользователей. Ключи JSON — разные случайные токены длиной не менее 32 символов
без пробелов. Замените заглушку ниже своим токеном:

```dotenv
HTTP_HOST=localhost
HTTP_PORT=8080
HTTP_DEMO_USERS='{"REPLACE_WITH_RANDOM_TOKEN_AT_LEAST_32_CHARS":{"role":"intern","team":"backend"}}'
```

При необходимости добавьте отдельных пользователей с ролью `buddy` или `manager`.
Токен даёт права именно своей записи. Команда должна совпадать с `team` документов;
`"team":""` даёт доступ только к документам без ограничения по команде.
Нет настройки пользователей/некорректная роль → сервер не запускается.
Не передавайте весь список токенов клиенту: frontend получает только токен
текущего пользователя. Это простой демо-механизм, не реализация корпоративной SSO.
Для запуска внутри контейнера задайте `HTTP_HOST=0.0.0.0`.

Если уже есть авторизация приложения, передайте собственный `Authenticator`,
который читает проверенную сессию или доверенный контекст middleware:

```go
server, err := FrontendAPI.NewHTTPServer(retriever, authenticate)
if err != nil { return err }
// main управляет ListenAndServe и Shutdown при завершении приложения.
err = server.ListenAndServe()
```

Сигнатура `authenticate`: `func(*http.Request) (rag.Access, error)`.
Для отсутствующей/некорректной сессии возвращайте `ErrUnauthenticated`, для
запрещённого доступа — `ErrForbidden`. Нельзя собирать Access из непроверенного
JSON, заголовков роли или параметров URL.

Если обработчик используется отдельно, новый конструктор:
`NewQuestionHandler(retriever, authenticate)`. Оба аргумента обязательны.

## Ошибки и ограничения

| HTTP | Условие |
| --- | --- |
| 400 | Некорректный JSON, лишние поля/данные, пустой вопрос |
| 401 | Отсутствующий, некорректный или неизвестный Bearer-токен |
| 403 | Запрет авторизации либо недопустимая роль/команда из authenticator |
| 405 | Метод, отличный от POST |
| 408 | Истёк таймаут чтения тела запроса |
| 413 | Тело запроса больше 1 MiB, включая данные после JSON |
| 415 | Content-Type не application/json |
| 500 | Ошибка backend/БД/модели; подробности идут в серверный лог |
| 504 | Истёк общий дедлайн или таймаут зависимости |

Чтение заголовков ограничено 5 с, всего запроса — 10 с. Общий контекст обработчика
(авторизация, чтение, RAG и LLM) — 2 минуты; запись — 2 минуты 15 с.
Отмена клиентом передаётся в RAG и LLM. Пустой контекст поиска возвращается как
обычный ответ 200 с сообщением о недостатке информации, без вызова LLM.
В лог не добавляются тело запроса, токен или полный вопрос.

Для frontend на другом origin настройте dev proxy на `/question` либо отдельную
политику CORS в приложении. Этот пакет сам CORS не включает.

Проверки: `go test ./FrontendAPI`, затем `go test ./...` и `go vet ./...`.
Тесты проверяют передачу Role/Team, запрет подмены прав, HTTP-контракт, ошибки,
размер тела, дедлайн/отмену, реальный медленный HTTP-запрос и связку с Retriever
при пустом контексте. БД и внешние модели для этих тестов не нужны.

При проверке 14 ноября 2026 нативные `go test -count=1 ./...`, `go build ./...`
и `go vet ./...` прошли. Покрытие FrontendAPI: 95,5% операторов. Повторить замер:

```powershell
go test -count=1 '-coverprofile=coverage.out' ./FrontendAPI
go tool cover '-func=coverage.out'
```

Это покрытие только HTTP-пакета, не всего backend. SQL integration-тесты
пропущены без `TEST_DATABASE_URL`; реальный сервис модели в этом прогоне не вызывался.
