# Локальные эмбеддинги: первый шаг

Содержимое архива копируется в корень проекта с сохранением папок.
`interfaces.py` включён без изменений. В `models.py` добавлены только
`TextChunk` и `EmbeddedChunk`; прежний `Chunk` используется для результатов поиска.

## Запуск

Нужен Python 3.10 или новее. Команды выполняются из корня проекта:

```bash
python -m pip install -r backend/requirements-embeddings.txt
python -m backend.rag.demo_embeddings
```

Первый вызов скачивает веса Qwen3-Embedding-0.6B. Затем используется кеш.
Полный запуск с весами в среде подготовки кода не проверялся: здесь нет
torch, sentence-transformers и весов. Зависимости заданы минимальными
версиями из документации модели, а не lock-файлом проверенного окружения.

## Настройки

| Переменная | По умолчанию |
| --- | --- |
| EMBEDDING_MODEL | Qwen/Qwen3-Embedding-0.6B |
| EMBEDDING_DEVICE | cpu |
| EMBEDDING_BATCH_SIZE | 8 |

Для NVIDIA GPU с подходящей установкой PyTorch задайте EMBEDDING_DEVICE=cuda.
EMBEDDING_MODEL также принимает путь к заранее скачанной модели Qwen.
Реализация ожидает размерность 1024 и сохранённый query-промпт.
RagConfig.from_env читает окружение процесса; файл .env сам не загружается.
EMBEDDER_URL удалён: отдельного HTTP-сервиса теперь нет.

## Как использовать

Один `QwenEmbedder(config)` создаётся при старте приложения и передаётся
в поиск и загрузку документов. Саму модель он загружает при первом вызове.
Кодирование выполняется в рабочем потоке, последовательно для одного экземпляра.
При нескольких процессах приложения каждый загружает собственную модель.

`await embedder.embed_query(question)` возвращает один вектор.
`await embedder.embed_documents(texts)` возвращает векторы в порядке текстов.
Векторы нормализованы. После кодирования выполняется дополнительная
L2-нормализация в Python float: это устраняет отклонения нормы, которые могут
остаться после вычислений модели в пониженной точности. Нулевые векторы,
NaN, бесконечность и неверная размерность по-прежнему вызывают ошибку.
При определении размерности предпочитается новый метод get_embedding_dimension,
с совместимостью со старым get_sentence_embedding_dimension.
Только запрос получает query-инструкцию модели.

`await embed_document(title, chunks, embedder)` принимает название документа
и готовые `TextChunk(section, text)`, возвращает `EmbeddedChunk(section, text, embedding)`.
При кодировании к тексту добавляются название и раздел; исходный текст сохраняется.
Эта низкоуровневая функция не читает файлы и не пишет в БД.
Для целого Markdown-файла теперь есть `prepare_document(path, chunker, embedder)`:
она читает метаданные, нарезает документ и вызывает `embed_document`.
Длинные тексты за пределами контекстного окна модель может обрезать:
передавать нужно небольшие чанки, не целые документы.

Чтение Markdown и чанкер описаны в README_chunking.md.
Далее добавляется загрузка документа и всех его чанков в БД одной транзакцией.
Нельзя смешивать в одном индексе векторы разных моделей; смена модели
или подготовки текста требует пересчёта индекса даже при той же размерности.

## Проверки без модели

```bash
python -m unittest discover -s backend/tests -v
```

15 проверок: настройки, пустые входы, query-промпт, батч, однократная загрузка,
последовательное выполнение, размерность и корректность векторов,
соответствие чанков векторам, нормализация после округления и новый API размерности.
Используется тестовая модель;
семантическое качество настоящей Qwen этими проверками не измеряется.
