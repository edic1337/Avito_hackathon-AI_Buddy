# RAG backend: контракт поведения

## Область

Go получает уже разделённые тексты `[]string`, вычисляет эмбеддинги через
OpenAI-совместимый HTTP endpoint, сохраняет их в PostgreSQL/pgvector и возвращает
контекст `[]string` для существующего `ModelAPI`. Чанкинг и инференс весов модели
остаются вне Go. Отдельной структуры Chunk в публичном API нет.

## Сценарии и критерии приёмки

1. Индексация: метаданные исходного документа + непустой `[]string` → батчи
   эмбеддингов → атомарная замена текстов одного source_key в одной коллекции.
   Повторная загрузка не создаёт дублей. Ошибка не оставляет половину документа.
2. Импорт: экспорт schema_version=1 из origin/RAG загружается без повторного
   инференса. Проверяются профиль, порядок, текст, размерность и конечность
   векторов. Неизвестная revision остаётся неизвестной; synthetic не становится public.
3. Поиск: роль и команда берутся вызывающим кодом из доверенной авторизации.
   Неизвестная роль — ошибка. intern < buddy < manager; manager не обходит team.
   Обе ветви поиска фильтруют ACL, активность и коллекцию до top-k.
4. Гибридный поиск: cosine + russian FTS, объединение по RRF (k=60).
   Порог применяется к cosine, не к FTS/RRF. Каждый выданный текст проходит порог.
   Возвращается до top-k строк с названием, разделом, происхождением и ссылкой.
5. Нет контекста → фиксированный ответ с предложением обратиться к наставнику,
   без вызова LLM. Сбой БД/эмбеддингов/LLM → ошибка, не «нет информации».
6. Query использует точный prompt_name=query из Qwen; документы — без query prompt.
   Векторы проверяются и нормализуются, ответы HTTP сопоставляются по index.
7. context.Context отменяет HTTP и SQL. Есть HTTP timeout и пределы объёма.
8. Текст источников считается данными, не инструкциями. Правила задаются system
   сообщением; синтетические инструкции явно помечаются в контексте.

## Проверки

Unit: HTTP контракт, батчи, порядок, некорректные векторы/ответы, отмена,
конфигурация, импорт, пустой контекст, ошибки LLM.
Integration (отдельная TEST_DATABASE_URL): миграции, идемпотентность, обновление,
конкурентные записи, rollback, ACL/команды/коллекции, FTS/RRF и cosine-порог.
Реальные модели нужны для оценки recall/MRR; эти тесты её не подменяют.
